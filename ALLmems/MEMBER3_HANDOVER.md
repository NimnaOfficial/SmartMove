# SmartMove Backend - Member 3 Handover Guide

Welcome to the SmartMove backend technical engine! As Member 3, I have completed the integration of the Spring Boot microservices, Spring Security (JWT), Oracle JPA connectors, and MongoDB aggregation pipelines. 

This guide contains everything you need to connect your frontend applications and databases to the backend.

## 🚀 1. How to Start the Backend

The project is built as a **Spring Boot Multi-Module Maven Project**. You do not need to start all 14 microservices manually if you only want to test a few, but for the full system to work, follow this exact boot sequence:

1. **Start the Service Registry (Eureka)**
   - Open a terminal in the root directory.
   - Run: `mvn spring-boot:run -pl services/service-registry`
   - Wait for it to start on **Port 8761**.

2. **Start the API Gateway**
   - Run: `mvn spring-boot:run -pl services/api-gateway`
   - Wait for it to start on **Port 8080**.

3. **Start the Business Microservices**
   - You can start individual services as needed (e.g., Auth, Booking, Passenger).
   - Example: `mvn spring-boot:run -pl services/auth-service`
   - All services will automatically register with Eureka and become available through the API Gateway.

## 🗄️ 3. Database Connection Configuration

Before starting the microservices, you must ensure your local databases are running and configured. You will need to add/update the `application.properties` (or `.yml`) files inside each microservice's `src/main/resources/` directory.

### Oracle Database (Standard Services)
```properties
spring.datasource.url=jdbc:oracle:thin:@localhost:1521:XE
spring.datasource.username=YOUR_ORACLE_USER
spring.datasource.password=YOUR_ORACLE_PASSWORD
spring.datasource.driver-class-name=oracle.jdbc.OracleDriver
spring.jpa.hibernate.ddl-auto=none
```
*(Note: `ddl-auto=none` is used because Member 1/4 already created the schema via `Oracle_Setup.sql`. The backend will not overwrite your tables).*

### MongoDB (Content Service Only)
```properties
spring.data.mongodb.uri=mongodb://localhost:27017/smartmove
```
*(Alternatively, use the Atlas URI from `atlas-credentials.env` if you are using cloud hosting).*

## 🔐 4. Authentication & Test Users

The backend is secured using **JWT (JSON Web Tokens)**. 
- To access protected endpoints, the frontend must first hit `POST /api/auth/login` with an email and password.
- The response will contain a `token`.
- For all subsequent requests, the frontend must include this token in the header:
  `Authorization: Bearer <your_jwt_token>`

**Required Test User Roles:**
When running the E2E demo for the viva, make sure you populate the database with at least:
1. An **ADMIN** user (to add vehicles, drivers, and view reports).
2. A **PASSENGER** user (to book trips and submit feedback).

## ⚠️ 5. Known Limitations & Important Rules

1. **Oracle PL/SQL Dependency:** The `report-service` and several native `@Query` search endpoints rely entirely on the exact table structures defined in `Oracle_Setup.sql`. If you alter table names or columns, the backend queries will crash.
2. **Missing Database Error (ORA-12514):** If you try to run the services without an active Oracle Database listener running on port 1521, the services will crash on startup. Always start Oracle Express/Enterprise Edition first!
3. **Trip-Route Mapping:** The Search queries use a `LEFT JOIN` between `TRIP` and `ROUTE`. This ensures trips without routes don't disappear, but be careful when creating trips in the UI to always assign a valid `ROUTE_ID`.
